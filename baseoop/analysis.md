1. Кандидаты в сущности

Из описания заказчика выделены следующие существительные, претендующие на роль классов:

| Существительное | Кандидат в класс? | Комментарий |
| Книга | Да | Основная сущность, хранит ISBN, автора, название, состояние |
| ISBN | Нет | Атрибут книги |
| Автор | Нет | Атрибут книги |
| Название | Нет | Атрибут книги |
| Читатель | Пока нет | В текущей постановке не различаются; можно не вводить класс User |
| Библиотека | Да | Хранилище книг и операций выдачи/возврата |
| Полка | Нет | Метафора места хранения; не требует отдельного класса |
| Список книг | Нет | Структура данных внутри Library |
| Состояние (доступна/выдана) | Нет | Атрибут книги |

2. Атрибуты и поведение кандидатов

Класс Book

Атрибуты:
- isbn: String - уникальный номер книги;
- author: String - автор;
- title: String - название;
- isAvailable: boolean - состояние: true - на полке, false - выдана.

Поведение:
- getIsbn(): String - вернуть ISBN;
- getAuthor(): String - вернуть автора;
- getTitle(): String - вернуть название;
- isAvailable(): boolean - проверить доступность;
- checkOut(): void - отметить книгу как выданную;
- returnBook(): void - отметить книгу как возвращённую.

Класс Library

Атрибуты:
- books: Map<String, Book> - коллекция книг, ключ - ISBN.

Поведение:
- addBook(book: Book): void - добавить книгу в фонд;
- findBookByIsbn(isbn: String): Book - найти книгу по ISBN;
- lendBook(isbn: String): void - выдать книгу читателю;
- returnBook(isbn: String): void - принять возврат книги;
- getAllBooks(): List<Book> - список всех книг;
- getAvailableBooks(): List<Book> - список доступных книг;
- getLentBooks(): List<Book> - список выданных книг.

3. Инварианты предметной области

1. Уникальность ISBN. В библиотеке не может быть двух книг с одинаковым ISBN.
2. Однозначность состояния. Книга не может быть одновременно выдана и доступна. В любой момент времени isAvailable либо true, либо false.
3. Запрет повторной выдачи. Если книга уже выдана, попытка выдать её снова должна приводить к явной ошибке.
4. Запрет возврата невыданной книги. Нельзя вернуть книгу, которая уже доступна.
5. Сохранение идентичности. ISBN, автор и название книги не меняются после создания экземпляра.

4. Открытые вопросы

- Нужно ли различать читателей и хранить, кто именно взял книгу? В текущей постановке - нет, но при развитии системы потребуется класс Reader и связь выдачи.
- Нужна ли история операций (кто, когда взял/вернул)? Пока не требуется.
